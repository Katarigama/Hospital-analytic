1. Разбор задачи

Задачу я разделил на несколько независимых условий:

1. диагноз должен быть установлен впервые;
2. диагноз должен находиться в диапазоне E40-E46;
3. диагноз должен быть установлен в январе-марте 2026 года;
4. пациент должен находиться на Д-учёте;
5. диагноз в Д-учёте должен совпадать с диагнозом;
6. до постановки на Д-учёт должен существовать профосмотр;
7. между профосмотром и постановкой на Д-учёт должно пройти не более 45 дней.

2. Построение первого запроса

Первоначально запрос создавался постепенно.

Сначала была взята таблица `patients`, после чего последовательно добавлялись:

- `visits`;
- `diagnoses`;
- `dispensary_registry`;
- профосмотры.

На каждом этапе проверялись не только итоговые значения, но и промежуточные записи.

3. Поиск профосмотра

Профосмотр хранится в `visits`, а не в `examinations`.

Для каждой записи диспансерного учёта необходимо найти последний профосмотр,
который произошёл не позже даты постановки на учёт.

Для этого используется `MAX(visit_date)`.

4. Оптимизация

После получения рабочего результата запрос был переработан.

Основные изменения:

- первичные диагнозы фильтруются до JOIN;
- записи активного Д-учёта фильтруются до JOIN;
- убраны таблицы, которые не влияют на итоговый результат;
- основной JOIN выполняется уже на уменьшенных наборах данных.

5. Почему такой подход

Сначала был построен простой рабочий запрос, потому что так легче проверить бизнес-логику.

После подтверждения корректности результата оптимизация выполнялась отдельно.

Такой подход снижает риск оптимизировать неправильную бизнес-логику.
